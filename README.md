# Терминал на Java · Вариант 7

Практическая работа по дисциплине «Конфигурационное управление»,
ИКБО-15-25, РТУ МИРЭА. Выполнены этапы 1 и 2 на Java/Swing:
графический REPL, параметры запуска и стартовый скрипт.
Основание: сборник практических работ № 1, вариант 7, страницы 26-27.

## Запуск и тесты

Нужен **JDK 17 или новее**, включающий `java` и `javac`, и графический
сеанс ОС. Maven, Gradle и внешние зависимости не нужны.
Скрипты предназначены для macOS/Linux и POSIX-оболочки.
Если установлено несколько JDK, задайте `JAVA_HOME`.

```sh
./run.sh                      # сборка и запуск GUI
./scripts/build.sh            # только компиляция
./scripts/test.sh             # проверки без графического сеанса
GUI_TESTS=1 ./scripts/test.sh  # дополнительно проверить настоящее окно
```

Команды сборки используют `javac --release 17 -encoding UTF-8`.
Классы записываются в `build/`, которая исключена из Git.
Запуск после сборки:

```sh
java -cp build/classes ru.mirea.emulator.Main
```

## Конфигурация (этап 2)

```sh
./run.sh --vfs examples/vfs.csv --startup-script examples/startup-success.txt
./run.sh --vfs "examples/paths with spaces/vfs demo.csv" \
  --startup-script "examples/paths with spaces/startup-error.txt"
./run.sh --help
```

| Параметр | Назначение | По умолчанию |
| --- | --- | --- |
| `--vfs ПУТЬ` | Физическое расположение VFS | Не задан |
| `--startup-script ПУТЬ` | Файл команд эмулятора в UTF-8 | Не задан |
| `-h`, `--help` | Справка без запуска GUI | Выключено |

Оба пути независимы и необязательны. Относительные пути отсчитываются
от текущей папки запуска, затем нормализуются в абсолютные.
Пути с пробелами заключайте в кавычки реальной оболочки.
Неизвестные, повторяющиеся параметры и отсутствующие значения дают
сообщение в stderr, справку и код выхода 2; GUI не запускается.
Справка возвращает код 0. Форма `--опция=значение` не поддерживается.

При запуске **в окне и stdout** печатаются значения `vfs` и
`startup-script`, включая явно не заданные параметры.
Путь VFS сохраняется в конфигурации; CSV-файл пока не загружается
и не проверяется, поскольку подключение VFS относится к этапу 3.
В `examples/` есть текстовые CSV-заготовки для демонстрации параметра.

Стартовый скрипт содержит по одной команде на строку.
Пустые строки пропускаются, но учитываются при нумерации ошибок.
Каждая команда и результат показаны в терминале GUI и продублированы
в stdout. Выполнение **останавливается при первой ошибке**:
следующие строки не исполняются, сообщение содержит путь и номер строки.
Ошибки чтения/кодировки файла также сообщаются в GUI и stderr.
После ошибки окно остаётся открытым для интерактивной работы;
`exit` в скрипте закрывает окно и останавливает оставшиеся команды.
Комментарии не входят в требования варианта 7: `#` не игнорируется.

### Скрипты реальной ОС

Каждый из следующих POSIX-скриптов запускает эмулятор с **обоими**
параметрами. Они работают и при запуске из другой папки.

```sh
./scripts/demo-success.sh   # все строки исполняются; затем доступен REPL
./scripts/demo-error.sh     # пути с пробелами; остановка на строке 3
./scripts/demo-exit.sh      # exit закрывает окно, строка 4 не исполняется
```

В первых двух демонстрациях окно закройте командой `exit`.
Для ошибки чтения:
`./run.sh --vfs examples/vfs.csv --startup-script examples/missing.txt`.

## Интерфейс терминала

Заголовок `Эмулятор - [username@hostname]` формируется по данным реальной
ОС. Тёмный фон, цветное приглашение `username@hostname:~$`, моноширинный
шрифт; ввод размещён прямо в общей области терминала.
Вывод предыдущих команд защищён от редактирования.
При вводе после клика по старому выводу текст попадает в текущую команду.

| Клавиша | Действие |
| --- | --- |
| Enter | Исполнить текущую строку |
| ↑ / ↓ | Предыдущая/следующая команда; возврат к черновику |
| Home | Начало текущего ввода после приглашения |
| Ctrl+A / Ctrl+E | Начало/конец текущей строки |
| Cmd+C / Cmd+V | Копирование/вставка в macOS |
| Ctrl+L | Очистить экран, сохранив текущий ввод и историю |
| Ctrl+C | Отменить ввод; при выделенном тексте копирует его |

Вставленный многострочный текст превращается в одну строку.
Для копирования и вставки также доступны стандартные сочетания ОС.
История хранит до 500 команд в памяти текущего сеанса.
Шрифт: JetBrains Mono, Menlo, Consolas или системный моноширинный.
Приглашение `~` пока декоративное: подключение VFS относится к этапу 3.

## Команды

| Команда | Аргументы | Результат |
| --- | --- | --- |
| `ls` | Ноль или один непустой путь | Имя команды и список аргументов |
| `cd` | Ноль или один непустой путь | Имя команды и список аргументов |
| `exit` | Без аргументов | Закрытие окна и завершение приложения |

`ls` и `cd` являются заглушками по условию этапа 1.
Опции и несколько путей считаются неверными аргументами.
Неизвестные команды и ошибки кавычек выводятся красным; REPL продолжает
работу. Реальные команды ОС не запускаются, файлы не изменяются.

Разбор поддерживает одинарные/двойные кавычки, объединение частей слова,
пустые аргументы и экранирование. В одинарных кавычках всё буквально;
в двойных обратный слеш экранирует `"`, `\`, `$`, обратную кавычку.
Вне кавычек слеш экранирует следующий символ.
Переменные окружения, конвейеры и подстановка команд не раскрываются.
Символ `#` является частью аргумента, комментарии не предусмотрены.

## Интерактивная демонстрация этапа 1

Запустите `./run.sh` и последовательно введите:

```text
ls
cd "мои документы"
ls 'папка с пробелами'
cd my\ documents
pwd
ls first second
cd -x
cd ""
ls "незакрытая кавычка
ls
exit лишний
exit
```

Первые четыре команды показывают заглушки и разбор кавычек.
Следующие пять показывают ошибки имени, аргументов и синтаксиса.
Повторный `ls` демонстрирует продолжение работы после ошибки.
`exit лишний` сообщает ошибку, `exit` закрывает окно.
Перед выходом проверьте ↑/↓, Ctrl+L и Ctrl+C.

## Структура и функции

Исходники: `src/main/java/ru/mirea/emulator/`.

| Класс | Назначение |
| --- | --- |
| `Main` | Точка входа; запуск Swing в потоке событий |
| `HostIdentity` | Данные ОС, формирование заголовка |
| `CommandParser` | `parse`: разбор строки на слова |
| `Shell` | `execute`: проверка и исполнение заглушек |
| `CommandResult` | Вывод, ошибка, признак выхода |
| `TerminalTheme` | Цвета, моноширинный шрифт, атрибуты текста |
| `TerminalPane` | `submit`, `input`, `replaceInput`; диалог и история |
| `TerminalWindow` | `open`, `terminal`; окно и оформление |
| `AppConfig` | `parse`, `defaults`, `debugLines`, `usage`; настройки запуска |
| `StartupRunner` | `run`; UTF-8 файл, диалог, остановка на ошибке/exit |

`tests/` содержит самостоятельные Java-тесты с явными проверками;
они работают без JUnit и флага `-ea`.
`CoreTests` проверяет синтаксис и команды; `GuiTests` проверяет окно,
историю, защиту вывода, очистку, отмену, скрипт и `exit`.
`ConfigTests` проверяет параметры и пробелы в путях; `StartupTests`
проверяет исполнение настоящих файлов, ошибки, UTF-8 и остановку.
`CliTests` запускает отдельные JVM и проверяет коды выхода.

## Проверка требований

| Требование | Реализация и демонстрация |
| --- | --- |
| GUI, заголовок из ОС | Swing, `HostIdentity`, `GuiTests` |
| Парсер кавычек | `CommandParser`, `CoreTests`, интерактивные примеры |
| Заглушки ls/cd, ошибки, exit | `Shell`, `CoreTests`, `GuiTests` |
| Интерактивная демонстрация | Сценарий этапа 1 выше |
| Параметры VFS/скрипта, отладочный вывод | `AppConfig`, `ConfigTests`, `CliTests` |
| Скрипт: ввод/вывод, первая ошибка | `StartupRunner`, `StartupTests`, `GuiTests` |
| Ошибка исполнения скрипта | Путь и номер строки; `demo-error.sh` |
| Несколько скриптов реальной ОС | `demo-success.sh`, `demo-error.sh`, `demo-exit.sh` |
| Отдельный коммит для каждого этапа | `git log --oneline` |

Каждый этап сохраняется отдельным коммитом Conventional Commits.
Репозиторий приватный по запросу владельца; методичка требует публичный
доступ, поэтому доступ для проверки следует согласовать перед сдачей.
