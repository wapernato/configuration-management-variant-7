# Терминал на Java · Вариант 7

Практическая работа по конфигурационному управлению, ИКБО-15-25.
Выполнены этапы 1-4: графический REPL, конфигурация, CSV VFS в памяти
и основные команды. Java 17+, Swing, без внешних зависимостей.

## Запуск

```sh
./run.sh --vfs examples/stage3/deep.csv
./run.sh --vfs examples/vfs.csv --startup-script examples/startup-success.txt
./run.sh --help
./scripts/build.sh
./scripts/test.sh
GUI_TESTS=1 ./scripts/test.sh
```

Нужен JDK 17+ с `java` и `javac`; при нескольких JDK задайте `JAVA_HOME`.
Скрипты работают в POSIX-оболочке macOS/Linux. Компиляция: `--release 17`.
Пути к реальным CSV и скрипту отсчитываются от папки запуска, пути с пробелами
заключаются в кавычки. `--vfs` и `--startup-script` независимы и необязательны.
Без `--vfs` дерево пустое: существует только `/`, поэтому `ls` ничего не выводит.
Данные VFS и реальные файлы компьютера - разные файловые системы.

## Команды

```text
ls [-al] [--] [пути...]
cd [путь]
pwd
wc [-lwcm] [--] файлы...
echo [-n] [аргументы...]
exit
```

Кавычки и экранирование поддерживаются. Неизвестные команды, неверные
опции, отсутствующие пути и ошибки синтаксиса показываются красным.
Переменные, конвейеры, перенаправления и подстановка команд не реализованы.
Подробнее о режимах и ограничениях - в README этапа 4.

## VFS и стартовые скрипты

VFS читается один раз из UTF-8 CSV `path,type,content`. Двоичные данные
файлов кодируются Base64; каталоги имеют пустое содержимое. Полные
канонические пути задают вложенность. Корень и родители объявлены явно.
Источник не изменяется, дерево хранится в памяти. Ошибка загрузки: stderr
и код процесса 3. Ошибка конфигурации: stderr, справка и код 2.
При запуске GUI и stdout показывают параметры и число узлов.

Стартовый скрипт - UTF-8, одна команда на строку. Пустые строки пропускаются,
`#` не является комментарием. На экране и в stdout видны команды и результаты.
При первой ошибке выполнение прекращается: путь и физический номер строки
показаны в stderr и GUI; окно остаётся открытым для интерактивной работы.
`exit` прекращает скрипт и закрывает окно.

```sh
./scripts/demo-vfs-minimal.sh
./scripts/demo-vfs-files.sh
./scripts/demo-vfs-deep.sh
./scripts/demo-vfs-invalid.sh
./scripts/demo-vfs-missing.sh
./scripts/demo-stage4.sh
./scripts/demo-stage4.sh missing
./scripts/demo-success.sh
./scripts/demo-error.sh
./scripts/demo-exit.sh
```

Демонстрации принимают все параметры запуска и работают из других папок.
Успешные демонстрации этапов 3/4 заканчиваются `exit`; `demo-success.sh`
оставляет интерактивное окно открытым. После ошибочной демонстрации
завершите сеанс командой `exit`.

## Интерфейс и код

Заголовок берётся из реальных `username@hostname`; приглашение показывает
виртуальную текущую папку. Enter исполняет команду; ↑/↓ - история с черновиком;
Ctrl+L - очистка; Ctrl+C - отмена ввода (при выделении копирует текст);
Home/Ctrl+A и Ctrl+E - начало/конец строки. В macOS доступны Cmd+C/Cmd+V.
История хранит до 500 команд. Старый вывод защищён от редактирования.

`src/main/java/ru/mirea/emulator/`: `CommandParser` разбирает кавычки,
`Shell` исполняет команды, `BasicCommands` реализует основные команды,
`VfsLoader`/`CsvReader` загружают дерево, `VirtualFileSystem` хранит данные,
`TerminalPane`/`TerminalWindow` реализуют GUI, `StartupRunner` читает скрипт.

Актуальные проверки находятся в `checks/`, работают без JUnit и `-ea`.
`build/` и `out/` не входят в Git. PDF README - отдельный экспорт документа.
Репозиторий приватный по запросу владельца; доступ преподавателю нужно
предоставить перед проверкой (методичка предусматривает публичный доступ).
