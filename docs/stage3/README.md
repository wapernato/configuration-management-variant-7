# Этап 3. Виртуальная файловая система

Вариант 7, Java 17+. Коммит этого этапа подключает CSV VFS в память.


CSV в UTF-8 имеет заголовок `path,type,content`. Полные абсолютные пути
задают вложенность. Тип - `directory` или `file`. Содержимое файлов
кодируется Base64; данные каталога должны быть пустыми. Корень `/`
и все родительские каталоги указываются явно, порядок записей не важен.
CSV поддерживает BOM, CRLF, запятые и удвоенные кавычки в полях.
Пути в CSV канонические: без `.`/`..`, повторов `/` и завершающего `/`.
Повторы путей, неверный тип, Base64, UTF-8 и отсутствующий родитель
отклоняются с сообщением об ошибке. CSV не распаковывается и не изменяется.

```sh
./scripts/demo-vfs-minimal.sh # один корень
./scripts/demo-vfs-files.sh   # несколько файлов, UTF-8, бинарный, пустой
./scripts/demo-vfs-deep.sh    # /a/b/c/deep.txt: три уровня каталогов
./scripts/demo-vfs-invalid.sh # неверное дерево
./scripts/demo-vfs-missing.sh # отсутствующий файл
./run.sh --vfs examples/stage3/deep.csv \
  --startup-script examples/stage3/startup-error.txt
```

В окне и stdout выводится число загруженных файлов и каталогов. На этом
этапе `ls`/`cd` ещё заглушки; полноценная логика будет в этапе 4.
`startup-arguments.txt` и `startup-quotes.txt` проверяют ошибки аргументов
и кавычек. Из-за остановки при первой ошибке они запускаются отдельно.

Проверки новых этапов находятся в `checks/`; `scripts/test.sh` запускает
`RegressionChecks` и `VfsChecks`. Последние проверяют CSV, глубокое дерево,
байты двоичного файла и неизменность исходного CSV.

## Проверка перед защитой

1. Покажите минимальную VFS, затем несколько файлов и дерево `/a/b/c`.
2. Покажите диагностическое число узлов в окне и stdout.
3. Запустите неверный и отсутствующий CSV: код выхода 3, понятная ошибка.
4. Выполните стартовые скрипты с неизвестной командой, ошибкой кавычек
   и аргументов: выполнение прекращается на первой ошибке.
5. Выполните `./scripts/test.sh`: проверяются также двоичные данные
   и сохранность исходного CSV. Все команды запускаются из корня проекта.

## Устройство реализации

`CsvReader` разбирает CSV; `VfsLoader` проверяет записи и родительские
каталоги; `VirtualFileSystem` хранит отсортированное дерево и байты файлов.
`Main` загружает VFS перед запуском Swing. При ошибке GUI не открывается.
Изменять CSV и создавать реальные файлы эмулятору не требуется.
